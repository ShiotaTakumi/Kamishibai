# 数理のスライドの書き方

定義・定理・証明を見せる発表のスライドを書くための規則です。
聴衆は各ページを話の速さで一度だけ読み、前のページへは戻れません。
そのため、ページの文は前から一度読むだけで、何が仮定で何が主張か、各記号が何を指すかが分かるように書きます。

この文書は Kamishibai の規則として置いていますが、Beamer や PowerPoint のスライドにもそのまま使えます。
人が書くときにも、AI にスライドを書かせるときや見直させるときにも、この文書を基本の規則として渡します（最後の節）。
例は日本語のスライドのものです。英語のスライドについての規則はまだ置いていません。

規則のうち、機械で確かめられるものは Kamishibai の検査が拒むか警告します（[engine/README.md](../engine/README.md) の「規則」）。
この文書は、機械では確かめられない書き方の規則を扱います。

## 1. ページに置くもの

- 定義・定理などの block には、主張の文だけを置きます。定義なら対象と条件、定理なら仮定と結論です。
  理由、証明の一歩、注意、「証明は後で」のような資料の都合は block の外に書きます。
- ページの番号で参照しません（「ページ 4 の補題」「次のページで示す」）。聴衆はページを戻れないので、定理の番号か内容の名前で言います（「補題 3.2」「全域木 $T$」）。
  番号と、番号で指す文は、エンジンに付けさせることもできます（[engine/README.md](../engine/README.md) の「主張の番号と参照」）。
- 聴衆への指示（「以下…と呼ぶ」「覚えておいてください」「前の図を思い出すと」）をページに書きません。
  定義の block の「〜を〜と呼ぶ」は指示でなく定義の文です。
- ページの内容の上に導入の文を置きません。ここで導入の文とは、題の下、block・箇条・図の前に置く文で、
  目的（「…を区別するための量」）、方針（「…を順に見る」）、先取り（「後で定理 4.2 で使う」）を述べるものです。
  動機と使い道は話して伝えます。ページの末尾のまとめの文も置きません。
  ただし、そのページで扱う対象を定める最初の文（「$G$ を次のグラフとする」）は内容なので残します。
  見分けるには、その文を消して題・block・図だけを読み、数学の主張や対象が欠けるかを見ます。
- 内容についての注記（「証明で一か所だけ使う条件」「この方法を使うには…が要る」）を書きません。
  条件や補題が何をするかは、数学の主張として書きます（「$G$ が木なら、…」）。
- 「（我々の知る限り）」のような、主張の確からしさを和らげる括弧書きを付けません。
  既知の結果の範囲を述べたいときは、出典を付けた文にします。
- その場で名付けた対象（「例のグラフ」）や前のページの図を、後のページが呼び名で指しません。
  使うページに描き直し、そのページの文で必要なことを述べます。定義のページで導入した数学の語と記号は別です。

## 2. 定義の書き方

定義の block では、何が何に対して定義される概念かを block の中で示します。
前提の文「〈対象〉を〈型〉とする。」で対象を固定し、改行して、被定義語の文を書きます。
被定義語の文は、次の三つの形から選びます。

- **基本の形**：説明を先に、名前を最後に置き、「〈説明〉を〈対象〉の〈概念〉と呼ぶ」（または「…という」）とします。
  聴衆は知っている語の説明を読み終えてから、新しい名前に出会います。

  > $G$ をグラフとする。
  > $G$ の全ての頂点を含む部分グラフで木であるものを、$G$ の全域木と呼ぶ。

  性質の定義は「〈条件〉のとき、〈対象〉を〈概念〉と呼ぶ」とし、記号の取り決めは「〜を $T_v$ とする」とします。
- **式だけで定まるとき**：新しい記号を一つの式で定め、言葉の説明が要らないときに限り、
  $\overset{\mathrm{def}}{:=}$（対象）と $\overset{\mathrm{def}}{\Longleftrightarrow}$（命題）を使います。

  > $G=(V,E)$ をグラフとする。
  > 頂点 $v\in V$ の次数 $\deg v\overset{\mathrm{def}}{:=}|\{e\in E : v\in e\}|$

  右辺に言葉が入るものや、既知の語に名前を付けるだけのものは基本の形にします。
- **条件が並ぶとき**：「〈対象〉の〈概念〉とは、以下の条件を満たす…のことを言う」「〈対象〉が〜であるとは、以下の条件が成り立つことを言う」と、
  被定義語を先に置き、条件を箇条か別の行の式で後ろに並べます。

そのほかの規則は次のとおりです。

- 「頂点の列で、隣り合う二つが辺で結ばれるものが道である」のように、既知の対象を主語、被定義語を述語に置きません。被定義語は主題か、「呼ぶ」の目的語に置きます。
- 前提の対象が前のページや block の外にしかない形（「$T$ の葉：…」だけ）にしません。前の定義で導入した対象を使うときは「$T$ を定義 2 の木とし」のように、定義の番号で前提の文に示します（エンジンに番号を付けさせるときは「$T$ を `\ref{tree}` の木とし」と書きます）。
- 一つの定義の block で名付ける新しい概念は一つにします。一つの構成の両側で切り離せない二語（外周と内周など）だけを同じ block に置きます。
- 定義を述べるためだけの補助の対象は、後で使わないなら名前を出さず、言葉か図で述べます。
- 定義と、その例・図を同じページに置きます。例は、定義の条件が働くもの（条件を外すと成り立たなくなるもの）を選びます。
- 定理の文に新しい概念が要るなら、定理の前にその概念の定義のページを置きます。

## 3. 定理の書き方

- 定理・補題・系は、「〈仮定〉とする。」で主張が何についてのものかを名指し、改行して「このとき〈結論〉」と書きます。
  仮定と結論を「〜なら、〜」の一文に詰めません。

  > $G$ を $n$ 頂点の連結なグラフとする。
  > このとき $G$ の辺の数は $n-1$ 以上である。

- 主張の中の記号は全て、その block の前提の文で導入します。取り決めや補助の記号を、主張の後ろに「（ただし $k$ は…）」と付け足しません。
  聴衆は前から一度読むので、後ろの但し書きは式を読む時点では効きません。
- 量化は語順で示します。短い式の中では $\forall,\exists$ を使ってよく、量化が長いときや二重以上のときは文に出して、式を別の行にします。
  存在の主張は「ある…があり、全ての…で〜」の順に書きます。
- 条件が二つ以上なら「以下の条件を満たす」で受けて箇条にし、結論が二つ以上なら (i)(ii) と番号を付けます。
  一つの項目には一つの主張だけを置きます。
- 含意を条件とするときや、定義の要の式は、文の中に埋めず別の行に出します。
- 改行してページがあふれるときは、改行を戻さず、図を文の横へ移すか、図の大きさを変えます。文字を小さくして収めません。
  エンジンは発表中にページからはみ出さないよう、あふれたページの文字を 85% まで自動で縮めますが、これは安全網です。縮んだページは編集モードの誤りの一覧に出るので、文か図を直して元の大きさに戻します。
- 未解決の問題は「未解決問題」の block に主張を書き、提起者を題の括弧に、出典を文献と問題の番号で示します。
  予想には名前を付けて主張を一文で止め、帰結は「予想が正しければ」の後に続けます。成り立つと見込む根拠を示さないまま、未解決の命題を予想と呼ばないようにします。

## 4. 証明と推論の書き方

- 日本語のスライドの本文は、体言止めを既定とします（「入力の結果を保存する」でなく「入力の結果の保存」）。
- ただし証明・確認・計算の推論は、体言止めにせず文で書きます。
  各段の主語と、前の段とのつながり（とすると、なので、すなわち、よって）を文の中に残し、結論は「〜である」で閉じます。
  名詞句を「、」「。」で並べただけの段は、どの量が何に対して定まり、何から何が従うかが読めません。

  > 悪い例：$T$ は $G$ の全域木、$e\notin T$。$T+e$ に閉路。
  >
  > 良い例：$T$ を $G$ の全域木とし、$e$ を $T$ に含まれない $G$ の辺とする。$e$ の両端は $T$ の中の道で結ばれるので、$T$ に $e$ を加えたグラフは閉路を含む。

- 一つの文には一つの主張を置きます。複数の主張の間の関係（論証の道筋、含意の連鎖、依存、対比、場合分け）は、文の中でなくページの構造で示します。
  「道筋：A → B（主定理）→ C」のように矢印や括弧で関係を一文に詰めると、聴衆は文を解析して関係を組み立てることになります。
  関係は、矢印でつないだ箱（矢印に根拠の名前を添える）、横に並べた列、ラベル付きの箇条、入れ子の箇条で示します。
  二つの対象を同じ量で比べるときは対象を列にした表にし、場合分けは場合ごとの項目に分けます。
  Kamishibai の block は主張専用なので、関係の図式には枠だけの箱（`div` とページの中の CSS）を使います。
- 関係を構造へ移す前に、その関係を聴衆が必要とするかを考え、要らない道筋は図にせず除きます。
- 証明の方針のページでは、各段階を「何から何を作り、何を保証するか」の一文にします。使う既知の結果は名前と出典を一行で示します。

## 5. 表記

- 細かい正確さを保つためだけの括弧書き・但し書きを入れません。正規化（「（合同を除く）」）、近似の断り（「（概数）」）、
  退化した場合の扱い、許す例外（「（ループと多重辺を許す）」）などで、主張を読む流れを止めるが聴衆の理解を変えないものです。
  厳密な形は定義のページか論文に置きます。ただし後の議論が依存する条件は残します。
- 出典は一つの形にそろえ、聴衆が開ける位置（文献、節、定理や問題の番号）まで示します。既定は著者名と年の [Author-Author Year] の形です。
  文の由来（「論文の記述」「発表者の整理」）は書きません。
- 数学の日本語では「組み合わせ」でなく「組合せ」と書きます。句読点は「、」「。」です。

## 6. 図

- 図にキャプションを付けません（図の下の説明文、「図：…」「左：…右：…」、色の凡例の文）。図の読み方は話して伝えます。
  図に付けた呼び名など後で使う名前は、ページの項目で導入します。
- 図はページの文の下に置きます。アルゴリズムの解説など、同じ図で段階を追う説明に限り、文を左、図を右に並べます。
- 図が比較・計数・対応を見せるなら、その答えを本文で先に言いません。
- 図のラベル・線の種類・色を本文の記号と語に一致させます。一つの図の要素に二つの役割を与えません。
- 図は表示する幅で描き、縮めて収めません。残った場所は、図を大きくするか、主張を見せる要素を足して使います。
- 数学の図は、手で近似して描かず、生成するプログラムで作り、図が表す性質（接続、面積、角度など）を確かめてから使います。

## 7. AI に書かせる・見直させるとき

AI にスライドを書かせるときは、この文書を指示に含めて渡し、上の規則に従って書くよう求めます。
見直させるときは、スライドの原稿とこの文書を渡し、次の問いでページごとに確かめさせます。
報告は、ページ、該当する文、反する規則（節の番号）、直し方の案の組にさせると、照合しやすくなります。

1. block に主張以外の文（理由、注意、資料の都合）が入っていないか。
2. ページの番号での参照、聴衆への指示、題の下の導入の文、内容についての注記、確からしさを和らげる括弧書きがないか。
3. 各定義は、前提の文と被定義語の文に分かれ、三つの形のどれかで書かれているか。$\overset{\mathrm{def}}{:=}$ は式だけで定まるものに限られているか。
4. 各定理は「〈仮定〉とする。」と「このとき〈結論〉」に分かれているか。主張の中の全ての記号が前提の文で導入されているか。後ろに付け足した但し書きがないか。
5. 量化の順は語順どおりか。一つの項目に二つの主張が入っていないか。
6. 証明の各段は、主語とつながりの語を持つ文になっているか。名詞句を並べただけの段がないか。
7. 複数の主張の関係を、矢印や括弧で一文に詰めていないか。
8. 正確さのためだけの括弧書きがないか。出典は一つの形にそろい、開ける位置まで示しているか。
9. 図にキャプションがないか。図は文の下にあるか。図の記号と本文の記号は一致しているか。

見直しの結果のうち、数学の主張そのものを変える直し（仮定を足す、主張を弱める）は、書き手が判断します。

# page-edit：ファイルとして開いた原稿へ書き戻す

Kamishibai の原稿（`engine/kamishibai.js` を読む HTML）を、ブラウザに表示したまま文と題を直し、
**原稿の HTML ファイルに直接書き戻す** Chrome の拡張です。原稿が唯一の正本で、別の形式や保存先は作りません。
WebSlide（`webslide.js` を読む HTML）にも同じように使えます。

- サーバーもアプリも使いません。原稿をファイルとして（`file://` で）ブラウザで開くと使えます。
- 読み書きの経路は一つだけです。**原稿を含むフォルダ（原稿のフォルダかその上のフォルダ）を一度許可すると、その下の原稿はどれも選ばずに開けます**
  （ブラウザの File System Access API。許可したフォルダはブラウザに残ります）。
- 原稿の HTML には何も足しません。この拡張を入れていなくても、どのブラウザでも今まで通り開けます。
- **Chrome・Edge・Brave など Chromium 系のブラウザが要ります**（Firefox と Safari では、原稿は開けますが書き込めません）。
- `make pack` で作った配布用ファイル（`.dist.html`）は直せません。直すのはその元の原稿で、直したら `make pack` で作り直します。

中身は [edit.js](edit.js)（編集の本体）と、拡張の [manifest.json](manifest.json)（`file://` のページに edit.js を差し込むだけ）です。

## 入れ方（その計算機で一度だけ）

1. Chrome のアドレス欄に `chrome://extensions` と入れて開き、右上の「デベロッパー モード」をオンにする。
2. 「パッケージ化されていない拡張機能を読み込む」を押し、この `page-edit` フォルダを選ぶ。
3. 出てきた page-edit の「詳細」を開き、「ファイルの URL へのアクセスを許可する」をオンにする。

拡張は一つの計算機に一つだけ入れます。原稿ごとに入れ直す必要はありません。
別の場所にある page-edit の写しを読み込んでいたときは、それを `chrome://extensions` で削除してから
このフォルダを読み込みます（どの写しも `manifest.json` の `key` が同じなので同じ拡張として扱われ、同時には入りません）。
page-edit が新しくなったときは、`chrome://extensions` の page-edit の再読み込みボタンを押します。

## 使い方

1. 原稿の HTML をファイルとしてブラウザで開く（`make preview SRC=…`）。
2. 初めてなら、ページの左の道具の欄をつまみで開いて「編集 ⌘E」のアイコン（鉛筆）を押すか ⌘E（Mac 以外は Ctrl+E）で、いま開いている原稿を含むフォルダを選び、書き込みを許可します（「毎回許可」を選ぶ）。
   一度許可したフォルダの下にある原稿は、開くだけでつながります
   （ブラウザを起動し直した後や、そのフォルダの原稿を全て閉じた後は、「編集」を押したときに許可の確認が一回出ることがあります。
   Chrome が確認や選択画面を出して待っている間は、その旨を道具の欄の上に出します。許可すると編集が始まり、
   取り消すか許可しないとプレゼンに戻ります）。
   Chrome の更新で前に許可したフォルダの記録が使えなくなったときは、その旨を出してフォルダの選択画面を開きます。もう一度選べば、次からはまた選ばずに開けます。
   選んだフォルダの中に開いている原稿が無いときは、その旨を出して何も書きません。
3. ⌘E か見出し「編集」で編集モードに入り、以下の操作で直します。
   エンジンの道具の欄（ページの左の隙間）には「編集」「プレゼン」「出力」の三つのモードが並び、編集モードの間は「編集」のアイコンが橙色に光ります。
   欄を畳んでも「編集」のアイコンだけはつまみの上に残ります（「保存しました」などの一言は欄の上に出ます）。
   編集モードの間は全ての文が原稿のまま（数式は `$…$` の TeX、文中のタグもそのまま）表示され、クリックしてもページはめくれません。
   英語を持つ原稿では、出している言語の文だけが表示され、書き換わります。日本語を出していれば日本語だけ、英語を出していれば英語だけです。
   言語はキー L か、道具の「あ」（日本語だけを編集）・「A」（英語だけを編集）で替えます。
   「あA」（日本語と英語を一度に編集）を押すと `<ja>…</ja><en>…</en>` の対がそのまま出て、両方を一度に直せます。どちらの表示かはブラウザが覚えます。
   英語の表示で、英語の無い文は灰色になり、直せません（「あ」か「あA」で直します）。
   プレゼンの道具（選択 ⌘I・キー無効 ⌘U・全画面など）や出力 ⌘P を押すと、編集モードから出てそのモードへ移ります。

| 操作 | 働き |
|---|---|
| ⌘E（Mac 以外は Ctrl+E） | 編集モードに入る・戻る。戻るとき編集中の文は保存する。原稿とまだつながっていなければ見出し「編集」と同じ |
| クリック（編集モードで） | その文（または題）を編集する。書き換えられる文はマウスを載せると点線の枠が出る |
| Enter | 保存（原稿に書き戻し、その場で組み直す。見ていたページと編集モードはそのまま） |
| Shift+Enter | 改行を入れる |
| Esc | 書きかけの文を保存せずに閉じる |
| ⌘Z（Mac 以外は Ctrl+Z） | 取り消し。直前の保存を元に戻す。文を編集している間は、打った文字の取り消し（ブラウザの働き） |
| ⇧⌘Z（Mac 以外は Ctrl+Shift+Z か Ctrl+Y） | やり直し。取り消した保存をもう一度行う |

取り消しとやり直しは、道具の欄の「取り消し」「やり直し」（曲がった矢印）でも行えます。戻せる保存が無い間は灰色です。

原稿をエディタや AI が書き換えたときも、1 秒ごとに見て自動で組み直します。
ページを再読み込みしても、許可が残っていればそのまま原稿とつながります。編集モードかどうかはタブを閉じるまで保たれます。

## 取り消しとやり直し

- **一回の取り消しで戻るのは、一回の保存です。** 章の名前や所属のように一度の保存で複数の箇所を書き換えたものも、まとめて戻ります。
  全て取り消すと、原稿は元のファイルとバイト単位で同じになります（改行コードや先頭の BOM も変えません）。
- 戻した箇所のページへ移り（片方の言語だけを直した保存なら、その言語に替え）、その箇所をしばらく色で示して、何を戻したかを道具の欄の上に出します。
- 文を編集している間の ⌘Z・⇧⌘Z は、打った文字の取り消し・やり直しです。保存か Esc で編集を終えると、保存の取り消しになります。
  編集モードの外と、ページの中の入力欄では、これらのキーを使いません。
- **外での変更は上書きしません。** 戻すときも原稿を読み直し、戻す箇所（とそのすぐ前後）が保存した直後のままであることを確かめます。
  別の場所がエディタや AI で変わっていれば、その変更を残したまま戻します。戻す箇所が変わっているか、一箇所に定まらないときは、
  何も書かずに理由を出します（複数の箇所の一つだけが変わっていても、どれも戻しません）。
  断られた取り消しは残り、外での変更が元に戻ればまた行えます。
- 履歴は原稿ごとに、タブを閉じるまで残ります（ページを再読み込みしても残ります）。新しく保存すると、やり直せる分は消えます。
  残すのは最近の 100 回までで、分量が多い（全体で約 100 万字を超える）ときは古い方から落とします。
- エディタや AI が書き換えた分は、ここでは取り消せません（そのエディタで戻します）。

## 書き換えられる範囲

- `p`・`item`・`note`・`down`・`block`（`alertblock`・`exampleblock`）・`proof`・`plan`・`later`・`slide` などの要素の中の文。
  中に `list` や `p` などの箱があるときは、箱の前・間・後の文がそれぞれ一つの文になります（`slide` に直に書いた `$$…$$` も直せます）。
  表紙の `headline`・`subtitle`・`author`・`meeting`・`date`、`figcaption`・`td`・`th`・`divider`・`column` も同様です。
- 一つの言語だけの表示での保存は、その言語の部分だけを書き換えます。もう一方の言語と、日本語の版の記録（`<en ja="…">`）は変えません。
  日本語だけを直した文の英語は、`make lang` で古い英語として出ます。
- 属性（英語の表示では `title-en` のように `-en` の付いた属性）：`slide`・`block`・`proof`・`plan`・`later` の `title`、`block` の出典 `cite`、`item` の `label`、表紙の `short`。
  章の名前 `sec`（各ページの上の見出し）と所属 `aff`（表紙の所属の行）は、同じ名前を持つ全ての箇所をまとめて書き換えます。
- 下の帯（フッター）の発表者・題・日付をクリックすると、表紙のページへ移ってその元の文（`short` があればそれ）を編集します。
- 箱の追加・削除・並べ替え、図、`<script>` の中、`caps` で文が切り替わる `figcaption`、エンジンが自分で出す文（「証明」などの既定の見出し）は対象外です（エディタで直す）。
- 保存のときは原稿を読み直し、画面を組んだ後にその箇所が変わっていれば書き込みません。そのときは今の原稿で組み直し、入力した文を知らせに残します。
  読み直してから書き込むまでの間に原稿が変わったとき（エディタでの保存など）も、書き込まずに同じように組み直します。
- 原稿から読んだ要素の並びとブラウザの並びが合わないときは、安全のため編集を止めて知らせます。

## 仕組み

拡張は `file://` のページ全てで edit.js を動かしますが、`.deck` を持つページ（エンジンが組んだページ）でなければ何もしません。
拡張は権限も background も持たず、edit.js を差し込むだけです。

原稿の読み書きは File System Access API だけで行います。

- 許可したフォルダの handle は、ブラウザの IndexedDB（`slide-edit` の `dirs`）に一覧で残します。
- 開いている原稿は、ページの URL のパスを、許可したフォルダの名前の位置からたどって探します。
  同じ名前の候補が複数あるときは、ページの最終更新時刻に最も近いファイルを選びます。
- 子のファイルはフォルダの許可を引き継ぎます。ページを開いたときは許可を尋ねず（すでに許可されていればつながる）、「編集」を押したときだけ確認を出します。

原稿を読むと、`kamishibai.js`（または `webslide.js`）の直前に edit.js の中身を差し込んだ形でページを組み直します（`document.open`/`write`）。
edit.js はエンジンが組み立てる前に、原稿のどの範囲がどの文かを要素ごとに印を付け、組み立て後の画面と原稿の位置を結びます。
原稿自身の `<script>` が最上位で `const`・`let` を宣言していると、組み直しで二重宣言になり動かないことがあります。

試しは見本の [engine/sample.html](../engine/sample.html) でできます。

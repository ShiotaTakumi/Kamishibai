# page-edit：ファイルとして開いた原稿へ書き戻す

Kamishibai の原稿（`engine/kamishibai.js` を読む HTML）を、ブラウザに表示したまま文と題を直し、
**原稿の HTML ファイルに直接書き戻す** Chrome の拡張です。原稿が唯一の正本で、別の形式や保存先は作りません。
WebSlide（`webslide.js` を読む HTML）にも同じように使えます。

- サーバーもアプリも使いません。原稿をファイルとして（`file://` で）ブラウザで開くと使えます。
- 読み書きの経路は一つだけです。**原稿を含むフォルダ（原稿のフォルダかその上のフォルダ）を一度許可すると、その下の原稿はどれも選ばずに開けます**
  （ブラウザの File System Access API。許可したフォルダは拡張の側に残り、開いたページのスクリプトからは使えません）。
- 原稿の HTML には何も足しません。この拡張を入れていなくても、どのブラウザでも今まで通り開けます。
- **Chrome・Edge・Brave など Chromium 系のブラウザが要ります**（Firefox と Safari では、原稿は開けますが書き込めません）。
- `make pack` で作った配布用ファイル（`.dist.html`）は直せません。直すのはその元の原稿で、直したら `make pack` で作り直します。

| ファイル | 役割 |
|---|---|
| [edit.js](edit.js) | 編集の本体。原稿のページの中で動く |
| [bridge.js](bridge.js) | ページと拡張の間で、依頼と返事を受け渡す |
| [files.js](files.js) | 原稿の読み書き（拡張の service worker） |
| [store.js](store.js) | 許可したフォルダの一覧と、その中の原稿の探し方（files.js と folder.js が使う） |
| [folder.html](folder.html)・[folder.js](folder.js) | フォルダを選び、許可する小窓 |
| [awake.html](awake.html) | 原稿のページに隠して置く空のページ（「小窓」の節） |
| [manifest.json](manifest.json) | 拡張の定義 |

## 入れ方（その計算機で一度だけ）

1. Chrome のアドレス欄に `chrome://extensions` と入れて開き、右上の「デベロッパー モード」をオンにする。
2. 「パッケージ化されていない拡張機能を読み込む」を押し、この `page-edit` フォルダを選ぶ。
3. 出てきた page-edit の「詳細」を開き、「ファイルの URL へのアクセスを許可する」をオンにする。

拡張は一つの計算機に一つだけ入れます。原稿ごとに入れ直す必要はありません。
別の場所にある page-edit の写しを読み込んでいたときは、それを `chrome://extensions` で削除してから
このフォルダを読み込みます（どの写しも `manifest.json` の `key` が同じなので同じ拡張として扱われ、同時には入りません）。
page-edit が新しくなったときは、`chrome://extensions` の page-edit の再読み込みボタンを押し、開いている原稿も再読み込みします。
3.11 までの版から 4.0 以降にしたときは、フォルダを一度だけ選び直します（前の版が覚えていた一覧は引き継げないので、原稿を開いたときに消します）。

## 使い方

1. 原稿の HTML をファイルとしてブラウザで開く（`make preview SRC=…`）。
2. 初めてなら、ページの左の道具の欄をつまみで開いて「編集 ⌘E」のアイコン（鉛筆）か ⌘E（Mac 以外は Ctrl+E）を押すと、拡張の小窓が開きます。
   いま開いている原稿を含むフォルダを小窓で選び、書き込みを許可します。許可すると、小窓は最小化し、編集が始まります。選び方は二つあり、結果は同じです。
   - Finder（Windows ではエクスプローラー）でフォルダが見えているときは、そのフォルダを小窓へドラッグします（枠の外に落としても構いません）。
   - そうでないときは「フォルダを選ぶ」を押します。このとき原稿のフォルダのパスがクリップボードに入る（前の中身は置き換わる）ので、
     Mac では、選ぶ画面で ⌘⇧G、⌘V、return の順に押すと、フォルダを探さずにそこへ移れます。そのまま選ぶ画面のボタンで決めます。
     Windows では「フォルダー」の欄に Ctrl+V で貼ります。
     Chrome は選ぶ画面を指定したパスで開くことを許していないので、開く場所を page-edit から決めることはできません。

   小窓は、編集している間は最小化したまま残し、編集している原稿のタブが無くなると自分で閉じます（[小窓](#小窓)）。
   選ぶのはその原稿のフォルダか、その原稿のプロジェクトのフォルダだけにします（ホームや書類の全体のような広いフォルダは選びません。[許可したフォルダ](#許可したフォルダ)）。
   許可の確認では「毎回許可」を選ばなくても使えます。毎回の確認を省きたいときだけ選びます。
   三つのモードの無い古いエンジンの原稿では、道具の欄に「編集 ⌘E」と「フォルダ」のボタンが出ます。
   一度許可したフォルダの下にある原稿は、開くだけでつながります
   （ブラウザを起動し直した後や、小窓を閉じた後は、「編集」を押したときか次に保存するときに小窓が開くことがあります。
   小窓の「フォルダ「…」の編集を許可する」を押すと続きます。小窓を開いて待っている間は、その旨を道具の欄の上に出します。
   許可すると編集が始まり、「やめる」を押すか小窓を閉じるとプレゼンに戻ります）。
   Chrome の更新で前に許可したフォルダの記録が使えなくなったときは、その旨を小窓に出します。もう一度選べば、次からはまた選ばずに開けます。
   選んだフォルダの中に開いている原稿が無いときは、その旨を小窓に出して何も書きません。
3. ⌘E か見出し「編集」で編集モードに入り、以下の操作で直します。
   エンジンの道具の欄（ページの左の隙間）には「編集」「プレゼン」「出力」の三つのモードが並び、編集モードの間は「編集」のアイコンが橙色に光ります。
   欄を畳んでも「編集」のアイコンだけはつまみの上に残ります（「保存しました」などの一言は欄の上に出ます）。
   編集モードの間も文は組んだ形のまま表示され、クリックしてもページはめくれません。
   クリックした文だけが、数式を `$…$` の TeX にした形に変わります。色・強調・太字・改行は見た目のまま出て、タグは見えません。
   英語を持つ原稿では、出している言語の文だけが表示され、書き換わります。日本語を出していれば日本語だけ、英語を出していれば英語だけです。
   エンジンが付けた番号と参照（`<html numbering>` の原稿）も組んだ形で出ます。クリックした題は番号の無い「定理（上界）」に、クリックした文の参照は `\ref{upper}` になり、
   直しても番号が文字として書き込まれることはありません。
   言語は、道具の欄の「日本語 ⇄ English」かキー L で、編集モードのまま替えられます（文を編集している間は、道具の欄で替えるとその文を保存してから替わります。キー L は文字として入ります）。
   「ダークモード」（キー D）も同じように替えられます。表示だけの切り替えで、原稿には何も書きません。
   英語の表示で、英語の無い日本語の文は灰色になり、直せません（日本語の表示で直します）。
   英語を新しく付けるときは、日本語の表示でその文を `<ja>…</ja><en>…</en>` に打ち替えるか、エディタで直します。
   プレゼンの道具（選択 ⌘I・キー無効 ⌘U・全画面など）や出力 ⌘P を押すと、編集モードから出てそのモードへ移ります。

| 操作 | 働き |
|---|---|
| ⌘E（Mac 以外は Ctrl+E） | 編集モードに入る・戻る。戻るとき編集中の文は保存する。原稿とまだつながっていなければ見出し「編集」と同じ |
| クリック（編集モードで） | その文（または題）を編集する。書き換えられる文はマウスを載せると点線の枠が出る |
| 文字を選んで ⌘K・⌘⇧K・⌘B | 強調・紺・太字にする。選んだ文字が全てその飾りなら外す。文字を選ばずに押すと、カーソルのある飾りを外す。色は一つだけで、別の色を付けると替わる |
| 編集中の文の上に出る小さな欄 | 選んだ文字の強調・紺・橙・青・緑・太字を付け外しする。↵ は改行 |
| Enter | 保存（原稿に書き戻し、その場で組み直す。見ていたページと編集モードはそのまま） |
| 文の外をクリックする（編集中の文から離れる） | Enter と同じく保存する |
| Shift+Enter | 改行を入れる |
| Esc | 書きかけの文を保存せずに閉じる |
| ⌘Z（Mac 以外は Ctrl+Z） | 取り消し。直前の保存を元に戻す。文を編集している間は、その文の入力と飾りを一つ戻す |
| ⇧⌘Z（Mac 以外は Ctrl+Shift+Z か Ctrl+Y） | やり直し。取り消した保存をもう一度行う。文を編集している間は、その文の入力と飾りのやり直し |

原稿に誤り（組めない数式、読めない画像、参照と番号、囲みの題、収まらないページ、編集できない文）があると、編集モードの間、
モードのアイコンの上に件数の付いた三角の印が出ます。押すと一覧が開き、行を選ぶとその場所へ移ります（[誤りの一覧](../engine/README.md#誤りの一覧編集モード)）。

取り消しとやり直しは、道具の欄の「取り消し」「やり直し」（曲がった矢印）でも行えます。戻せる保存が無い間は灰色です。

⌘ は Mac 以外では Ctrl です。

原稿をエディタや AI が書き換えたときも、1 秒ごとに見て自動で組み直します。
原稿が消えたり読めなくなったりしたときは、そのことを一度だけ出します（読めるようになると、また自動で組み直します）。
ページを再読み込みしても、許可が残っていればそのまま原稿とつながります。編集モードかどうかはタブを閉じるまで保たれます。

## 取り消しとやり直し

- **一回の取り消しで戻るのは、一回の保存です。** 章の名前や所属のように一度の保存で複数の箇所を書き換えたものも、まとめて戻ります。
  全て取り消すと、原稿は元のファイルとバイト単位で同じになります（改行コードや先頭の BOM も変えません）。
- 保存でも、直さなかった部分はバイト単位でそのままです（文字としての改行なしの空白 U+00A0、行末とその後の字下げ、属性の値の中の改行も変えません）。
  例外は次のとおりです。引用符の無い属性（`sec=終わり`）は保存すると `"…"` で囲みます。属性の中で打った改行は空白に、打った引用符は `&quot;`（`'…'` で囲んだ値では `&#39;`）になります。
  数式の中で打った `<` のうち HTML がタグの始まりと読むもの（すぐ後が英字・`!`・`?`・`/`）は `&lt;` になります。
  原稿のその文が数式の中の `<`・`>` を全て `&lt;`・`&gt;` と書いているときは、打った `<`・`>` もそれにそろえます。
- 戻した箇所のページへ移り（英語を持つ原稿では、その保存をした言語に替え）、その箇所をしばらく色で示して、何を戻したかを道具の欄の上に出します。
- 文を編集している間の ⌘Z・⇧⌘Z は、その文の入力と飾りの取り消し・やり直しです。保存か Esc で編集を終えると、保存の取り消しになります。
  編集モードの外と、ページの中の入力欄では、これらのキーを使いません。ページのスクリプトが作ったキーの操作でも動きません。
  保存や組み直しの途中、文を編集している間に保存の取り消し・やり直しを押したときは、何もしなかった理由を出します。
- **外での変更は上書きしません。** 戻すときも原稿を読み直し、戻す箇所（とそのすぐ前後）が保存した直後のままであることを確かめます。
  別の場所がエディタや AI で変わっていれば、その変更を残したまま戻します。戻す箇所が変わっているか、一箇所に定まらないときは、
  何も書かずに理由を出します（複数の箇所の一つだけが変わっていても、どれも戻しません）。
  断られた取り消しは残り、外での変更が元に戻ればまた行えます。
- 履歴は原稿ごとに、タブを閉じるまで残ります（ページを再読み込みしても残ります）。新しく保存すると、やり直せる分は消えます。
  残すのは最近の 100 回までで、分量が多い（全体で約 100 万字を超える）ときは古い方から落とします。
- エディタや AI が書き換えた分は、ここでは取り消せません（そのエディタで戻します）。

## 書き換えられる範囲

- `p`・`item`・`note`・`down`・`block`（`alertblock`・`exampleblock`）・`proof`・`plan`・`later`・`slide` などの要素の中の文。
  中に `list` や `p` などの箱があるときは、箱の前・間・後の文がそれぞれ一つの文になります（`slide` に直に書いた `$$…$$` も直せます）。
  表紙の `headline`・`subtitle`・`author`・`meeting`・`date`、`figcaption`・`td`・`th`・`divider`・`column` も同様です。
  流れ図の `box`・`to`、囲み `boxed`、アルゴリズムの `io`・`ln`、出典 `credit` も直せます。
- 編集中の文で原稿の書き方のまま出るのは、数式（TeX）、`&nbsp;` などの文字参照、文字としての `$` を表す `\$`、コメント、`<img>` や `<a>` などのタグだけです
  （`\$` は画面の `$` 一文字として数え、数式の始まりとは読みません。エンジンと同じです）。
  強調 `alert`・色・太字 `b`・出典 `cite`・`span`（ラベルなど）・注釈 `rem` などの文中のタグと、改行 `br` は見た目で出ます。
  道具の欄とキーで付け外しできるのは、強調・紺・橙・青・緑・太字です。ほかのタグを足すときはエディタで直します。
- 見た目の形から原稿へ同じに戻せない文（ゼロ幅の空白 U+200B を含む、改行が CRLF、文の中でタグの開け閉めが閉じていない、など）は、
  タグも原稿の書き方のまま出ます。そのときは理由を道具の欄の上に出し、飾りの欄とキー（⌘K・⌘⇧K・⌘B）は使えません。
- 文字としての `<` は `&lt;` と書くか、数式 `$…$` の中に入れます。HTML がタグの始まりと読む `<`（すぐ後が英字・`!`・`?`・`/`）を打って、
  タグの開け閉めが合わなくなるときや、ページの要素の並びが変わるときは、保存せずに編集中の文を開いたまま理由を出します（貼り付けも同じです）。
  閉じたタグ（`<b>…</b>` など）と、すぐ後が空白の `<`、`&` は打ったとおりに書き込みます（`&` を `&amp;` には変えません）。
- 英語を持つ原稿での保存は、出している言語の部分だけを書き換えます。もう一方の言語と、日本語の版の記録（`<en ja="…">`）は変えません。
  日本語だけを直した文の英語は、`make lang` で古い英語として出ます。
- 属性（英語の表示では `title-en` のように `-en` の付いた属性）：`slide`・`block`・`proof`・`plan`・`later`・`box`・`boxed`・`algo` の `title`、`block` の出典 `cite`、`item` の `label`、表紙の `short`。
  章の名前 `sec`（各ページの上の見出し）と所属 `aff`（表紙の所属の行）は、同じ名前を持つ全ての箇所をまとめて書き換えます。
  英語の名前 `sec-en`・`aff-en` は、同じ英語を持ち、しかも同じ要素の日本語の名前（`sec`・`aff`）も同じ箇所だけを書き換えます（別の章が偶然同じ英語の名前でも変えません）。
- 下の帯（フッター）の発表者・題・日付をクリックすると、表紙のページへ移ってその元の文（`short` があればそれ）を編集します。
- 箱の追加・削除・並べ替え、図、`<script>` の中、`caps` で文が切り替わる `figcaption`、エンジンが自分で出す文（「証明」などの既定の見出し）は対象外です（エディタで直す）。
- 保存のときは原稿を読み直し、画面を組んだ後にその箇所が変わっていれば書き込みません。そのときは今の原稿で組み直し、入力した文を「閉じる」を押すまで残る知らせに出します。
  読み直してから書き込むまでの間に原稿が変わったとき（エディタでの保存など）も、書き込まずに同じように組み直します。
  ただし、最後に確かめてから書き込みが始まるまでのごく短い間の変更は、File System Access API にファイルを固定する手段が無いので防げません（その変更は上書きされます）。
- 書き込みに失敗したとき（ほかのプログラムが原稿を使っている、許可が無い、など）は、理由と入力した文を「閉じる」を押すまで残る知らせに出します。
- 原稿から読んだ要素の並びとブラウザの並びが合わないときは、安全のため編集を止めて知らせます。始めに食い違う場所（原稿の行番号とページ）は、誤りの一覧に出ます。

## 許可したフォルダ

- page-edit が覚えているフォルダの一覧は、拡張の側（Chrome のプロファイルごと）に置きます。開いたページのスクリプトは、フォルダにも、その中のほかのファイルにも届きません。
  ページが拡張に頼めるのは、**そのページ自身の原稿の読み書き**と、その隣への `名前.dist.html` の書き出しです。
  クリックやキーの操作の直後には、覚えているフォルダの名前を見ることと、忘れることも頼めます。
  どの原稿かはページの申告でなく Chrome が拡張に知らせる URL で決めるので、ほかの原稿の読み書きは頼めません。
- 許可したフォルダの中にある HTML は、開くとそのスクリプトが自分のファイルを書き換えられます。書き出しは、その HTML が指すフォルダの中のファイルを一つにまとめます。
  だから、選ぶのは原稿のフォルダかそのプロジェクトのフォルダだけにし、知らない HTML ファイルをそのフォルダに置かないようにします。
- 「毎回許可」は、Chrome を起動し直すたびの確認を省きたいときだけ選びます。選ばなければ、許可は小窓を閉じるか Chrome を終了すると消えます（フォルダの一覧は残り、次に「編集」を押したときに小窓が出ます）。
- 一覧は、編集モードの道具の欄の「覚えているフォルダ」（フォルダのアイコン。古いエンジンでは「フォルダ」のボタン）で見られます。
  「忘れる」でそのフォルダを、「全て忘れる」で全てを一覧から外します。忘れたフォルダは、次に「編集」を押したときに選び直します
  （いま開いているタブは、再読み込みするまで今の原稿に書けます）。
- Chrome が与えた許可そのものは、Chrome の設定（`chrome://settings/content/filesystem`）で取り消します。
- 一時的に応答しないフォルダ（スリープの後やネットワーク上のドライブ）は、一覧から外しません。外すのは、無くなったとわかったフォルダだけです。

### 小窓

「今回のみ許可」の許可は、拡張の窓が一つも無くなると Chrome が取り消します。そこで、許可の後も小窓を一つだけ最小化して残します。

- 小窓を閉じたときは、次の保存のときに小窓がもう一度開きます。許可すれば、その保存がそのまま行われます（書いた文は失われません）。
- 「毎回許可」のフォルダでは許可が消えないので、小窓は要りません。「毎回許可」を選んだその回だけは最小化して残りますが、閉じて構いません。次からは小窓を開かずにつながります。
- 小窓を最小化すると、Chrome は拡張の処理の優先度を下げるので、計算機が混んでいるときに保存が数十秒遅れることがあります。
  これを避けるため、フォルダを許可した原稿のページ（と、拡張に依頼をしている間のページ）に、拡張の空のページ（awake.html）を見えない大きさ（1 ピクセル、透明）で置きます。
  優先度は、その原稿のページが画面に見えている間だけ普通に戻ります。原稿のファイル、書き出した HTML、印刷には何も入りません。

## 仕組み

拡張は `file://` のページ全てで edit.js を動かしますが、`.deck` を持つページ（エンジンが組んだページ）でなければ何もしません。
原稿の読み書きは File System Access API だけで行い、フォルダとファイルの handle は拡張の側（service worker の files.js と小窓）だけが持ちます。
edit.js は bridge.js を通して依頼を送り、文・更新時刻・大きさ・フォルダの名前だけを受け取ります。
拡張が求める権限は `file://` のページを読むこと（`host_permissions`）だけです。

- 許可したフォルダの handle は、拡張の IndexedDB（`page-edit` の `dirs`）に一覧で残します。
  3.11 までの版がページの側の IndexedDB（`page-edit`・`slide-edit`）に残した一覧は、使わずに消します。
- フォルダの選択画面と許可の確認は、拡張のページでのクリックかドロップを要するので、小窓（folder.html）で行います。
  ドロップで Chrome が渡すのも選択画面と同じ handle で、パスは渡されません。読み取りだけが許可された状態で届くので、
  原稿が中にあることを先に確かめ、あるときだけ書き込みの許可を尋ねます。
  許可の後に残る小窓は、落とされたものを受け取らず、その表示に切り替わることもありません。
- 開いている原稿は、ページの URL のパスを、許可したフォルダの名前の位置からたどって探します。
  handle は自分の場所を知らないので、見つけたファイルの中身がページの URL のファイルと同じことを確かめ、違えば使いません。
  中身の同じ候補が複数あるときは、許可した全てのフォルダの中から、ページの最終更新時刻に最も近いファイルを選びます。
- 子のファイルはフォルダの許可を引き継ぎます。ページを開いたときは許可を尋ねず（すでに許可されていればつながる）、「編集」や保存の操作で要るときだけ小窓を出します。

原稿を読むと、`kamishibai.js`（または `webslide.js`）の直前に edit.js の中身を差し込んだ形でページを組み直します（`document.open`/`write`）。
edit.js はエンジンが組み立てる前に、原稿のどの範囲がどの文かを要素ごとに印を付け、組み立て後の画面と原稿の位置を結びます。
原稿自身の `<script>` が最上位で `const`・`let` を宣言していると、組み直しで二重宣言になり動かないことがあります。
原稿の `Content-Security-Policy`（`<meta http-equiv>`）がページの中の `<script>` を止めていると、組み直したページで edit.js が動きません。
組み直しに失敗したときは、その旨と原因を道具の欄の上に出します（ページを再読み込みすると元に戻ります）。

試しは見本の [engine/sample.html](../engine/sample.html) でできます。
